# 后续版本：功能取舍与实用增量

2026-09-09 用户明确要求：后续版本重点剔除没用的功能，增加实用功能。本文件约束后续版本选题；以下为下一阶段方案，未实现项不计入已完成。

## 判断标准

- 主要服务办公文件的“选择输入 → 批量处理 → 核对 → 继续处理”。能减少一次重复选文件、一次重复配置或一次人工核对的功能优先。
- 相同任务已有可用能力时，优先改进原入口；新增标签页、模块或第二套实现需要说明现有能力为什么覆盖不了。
- 剔除分为合并重复入口、移走不相关的默认推荐、删除无调用或已被替代的实现。隐藏入口只算交互减法，不冒充代码删除。
- 当前没有可靠的使用频次统计。先按职责重合、主流程关联和真实可用性判断，不把默认关闭直接判为无用，不为统计增加云端采集。
- 删除功能同时核对导航、命令搜索、模块开关、操作目录、接力路由、内置模板和已保存工作流。旧历史仍可查看；需要迁移的旧操作 ID 提供明确映射或不可执行原因，不清除用户数据。

## 已核对的现状与取舍

依据：`gui/src/config/tools.js`、`api/tasks.py`、`gui/src/components/TaskCenter.vue` 及当前设计文档。

| 对象 | 当前事实 | 后续决策 | 验收要求 |
| --- | --- | --- | --- |
| 两处 PDF 合并 | 转换中心合并完整文件；PDF 工具支持每份文件页码范围，能力不完全相同 | 合并用户入口，保留明确的整文件/页码范围选择及必要的引擎能力 | 原有两条接力路由、模板和旧工作流仍能找到等价操作；页码范围不丢失 |

| 图片命名与文件重命名 | 两处都有批量命名，图片入口可能有格式或图片专属规则 | 对照规则后合并通用部分，专属规则作为模式保留 | 原命名结果、冲突处理、预演和撤销保持一致 |

| 系统进程、启动项查看 | Windows 专用、已默认关闭，通用系统工具已有替代 | 不继续扩建通用系统管理器；作为整模块精简候选，若需要文件占用诊断则嵌入具体失败场景 | 应用健康、备份恢复和任务诊断继续可用；删除前核对实际引用 |
| 印章图像 | 已默认关闭，可用作图片水印素材 | 保持可选，停止扩展孤立样式；有替代且无明确工作链路时再删除专属实现 | 不将“原本关闭”记作本轮删减成果 |
| 视频 | 已默认关闭，依赖 FFmpeg，但压缩、截取、音频提取有明确用途 | 保留可选，仅按实际需求修复，不因依赖较大就删除 | 缺依赖可解释，已有工作流仍能识别相应操作 |
| 重试与历史导出 | 已能只重试失败项，已有 JSON 完整记录与 CSV 任务摘要 | 直接扩展现有任务中心，不再新建“重试工具”或“历史导出模块” | 新增能力与已有自动重试、任务摘要能清楚区分 |

## 下一阶段优先实现

### P0：从失败明细回到原工具修正

场景：一批文件中部分失败，用户需要改质量、格式或字段映射再处理，现有“按原参数重试”不能满足修改参数的需求。

- 输入：已选任务、已选失败项及原操作可恢复的非敏感参数。
- 处理：从实际 `itemResults/inputItems` 提取失败输入，按 `primaryInputFields` 和原操作的单/多文件约束生成编辑草稿；用户检查并修改后再提交。
- 输出：原工具中已填好的失败输入及参数。接收草稿本身不入队，不包含先前成功项。
- 异常：缺失文件显示原因；页码标识、网页请求标识等不能假装成普通文件路径；已脱敏或体积过大的参数要求重新填写；不兼容操作保留失败详情，不错误映射。
- 协作：复用任务中心、主输入登记、现有接力与工作区。失败任务的输入不能伪装为它生成的输出；来源关系只沿用已有可验证信息。
- 验收：混合成功/失败、单文件工具、缺失输入、修改参数、敏感参数、重复路径和非文件失败项均可解释；接收前后队列数量不变，用户显式运行才新增任务。
- 复杂度：中等。先支持已登记的文件批处理操作，其余类型明确不支持，不设计任意参数恢复器。

### P0：在现有导出中补齐逐文件核对清单

场景：当前 CSV 每行是一个任务，批量任务中的单份失败和对应产物仍需逐个打开核对。

- 输入：当前明确选定的任务或筛选范围，以及“任务摘要/逐文件明细”粒度。
- 处理：复用真实逐项记录输出任务 ID、输入、状态、原因和已确认的输出；一对多产物按明确行规则展开，无法确认映射时写“未记录”，不按文件名猜测。
- 输出：可在 Excel 打开的 CSV 明细，沿用既有导出入口；记录导出范围及数量，用户可继续筛选失败行。
- 异常：老记录缺逐项数据时保留任务摘要并说明；大范围导出设置预算和进度；公式样式文字保持文本语义，不导出敏感参数。
- 协作：共享任务历史和现有 CSV 导出，不增加独立扫描器、任务数据库或报告模块。
- 验收：一项多产物、部分失败、来源已清理、旧记录、空范围和包含换行/逗号的原因都能正确导出；明细数量与实际范围一致。
- 复杂度：中等。先完成确定映射的数据，不能以看似完整的空字段掩盖缺失信息。

### P1：统一现有预演与冲突说明

先核对分类、重命名等已有预演，不重复建设。仅补齐缺口：来源 → 计划去向、覆盖/避让规则、跳过原因及范围统计；复用执行时的规则函数。预演不锁定文件名，输入改变后清除旧计划，真正执行仍重新核对。

## 实施顺序与发布要求

1. 首轮完成调用与入口清单，选一组重复入口做实质收敛，并实现失败项修正这一条完整流程；不把大量候选同时塞进一个版本。
2. 次轮扩展已有导出的逐文件核对能力，继续删除已完成替代和迁移的重复代码。
3. 每轮记录“删除了什么、合并到哪里、新能力减少了哪一步人工操作、哪些旧数据继续可用”。没有明确收益的候选不进入实现。
4. 将功能减法与完整实用增量合并验证后发布；单次推荐位或文案调整不单独发版。提交推送后用附注 Tag 触发 GitHub 自动发布，三平台通过才生成正式 Release。

更复杂的自动链路推荐、通用 AI 决策、全盘常驻索引和新增孤立模块继续后置。实际删除清单与下一版本范围在实施前依据代码引用和兼容结果确定，不能把本方案写成已经完成的删除。
