# PPX v2.17.4 — 浏览器采集故障修复

修复浏览器采集在冻结安装包和异步界面流程中的启动与等待问题，并在目标网页要求人工验证时保留会话、明确告知用户。

## 修复

- 冻结应用通过随包 Node CLI 调用 Playwright，避免把应用自身的 `sys.executable` 当作 Python 模块启动器。
- 浏览器驱动检查区分未安装与检测失败，增加就绪等待和可重试的错误状态；诊断信息限制范围并脱敏。
- 修复 Playwright 同步桥接回调的等待方式，避免浏览器操作卡在主线程的同步休眠中。
- 容器匹配数量与样本文本分别传递，修复点选后数量显示错误。
- Google 异常流量验证页会在采集前提示人工验证并保留浏览器会话，不把验证页内容导出为采集结果。
- 增加实际驱动安装命令的 `--dry-run` 检查；dry-run 仅检查命令计划，不等于安装完成。

## 验证范围

190 项 Python 测试、25 项前端合同检查、静态检查、生产构建、完整工作区 E2E 和界面巡检通过。真实工具条点选、两行预览、正式采集、Excel 导出并重新读取核对通过。

通过产品 API 的有头浏览器访问用户提供的 `https://www.google.com.hk/search?q=123`，实际点选后预览及正式采集各得到两行，JSON 导出成功。独立无头预检曾遇到 Google 异常流量验证页；另用本地夹具验证了提示人工验证、保留会话及恢复采集，不将验证页当作搜索结果。

最终 Windows 冻结程序从空隔离缓存通过真实 API 下载 Chromium，并实际启动读取本地页面；包内桥接、AES 页码切割、图像和 OCR 冒烟通过。原生界面首次下载操作未完成验收；不等同于安装器安装、升级和恢复验收。其他 DPI、多屏、CEF、广泛 OCR 和 LibreOffice 验收继续保持 pending。证据见 [验证清单](assets/v2.17.4/verification.json)。
