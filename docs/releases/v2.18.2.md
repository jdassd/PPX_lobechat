# PPX v2.18.2 — 网页采集默认浏览器缓存修正

修复 Windows 冻结版网页采集显示浏览器已就绪、开始点选后却无法启动 Chromium 的问题。状态检测、浏览器安装和启动现在使用相同的默认 Playwright 缓存位置，启动时明确使用已安装的浏览器程序；环境下载完成后可重新检测并继续。

此前一次空缓存验证显式设置了 `PLAYWRIGHT_BROWSERS_PATH`，没有覆盖普通默认环境。这是测试覆盖缺口，旧结果不作为默认缓存路径正常的证据。本版增加冻结程序默认路径 probe，并要求最终冻结包在父进程没有设置该变量的环境下验证冷缓存安装和启动。

本地验证通过：206 项 Python 测试、26 项前端合约、静态检查、生产构建、完整工作流程与界面扫描。完整 Windows 冻结程序在空的隔离默认缓存中，未设置 `PLAYWRIGHT_BROWSERS_PATH`，实际下载 Chromium 后通过采集接口启动并收到工具条就绪事件；同时通过桌面桥接、AES PDF 切割、CAJ、OCR 和图片处理检查。错误恢复界面在 1280×800、960×640 下可操作，重新检测保留网址与配置。详细证据见 [验证记录](assets/v2.18.2/verification.json)。

浏览器自动验证使用测试专用无头模式，产品仍正常打开可见浏览器；不将此结果当作原生人工点选或 Windows 合成器闪烁验收。错误界面交互使用注入的 API 错误，与真实冻结启动验证分别记录。

原生安装、升级、恢复、其他 DPI/多屏、CEF、广泛 OCR 和 LibreOffice 验收继续依照 [验收清单](../refactor-acceptance.json) 保持 pending。正式安装包必须来自已推送 v2.18.2 标签提交的三平台成功 CI。
