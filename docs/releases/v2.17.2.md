# PPX v2.17.2 — 修复加密 PDF 与 Windows 窗口缩放

针对实际使用反馈，补齐此前普通 PDF、浏览器回归未覆盖的 AES 加密文件和 Windows 原生窗口路径。

## 修复

- 打包包含 `PyCryptodome` 及其 AES 原生依赖；切割、分段拆分、多文件切割和合并统一处理加密 PDF，明确提示缺少密码或密码错误。普通 PDF 忽略无关密码。
- PDF 切割、拆分增加打开密码；合并可按文件分别填写密码和页码。切换来源清空旧密码和结果，密码不进入工作区与任务历史；工作流拒绝保存非空 PDF 密码，并提示使用 PDF 工具手动处理。
- Windows 默认窗口按可用工作区与 DPI 计算，避免显示后再次缩小；兼容旧物理像素窗口记录，恢复时约束离屏尺寸与位置。保存时补偿 WinForms 构造窗口扣除的尺寸，避免每次重启继续变小。最大化避开任务栏。
- Windows 无标题栏窗口恢复原生缩放框架，保留独立的原生边缘区域。缩放由系统直接处理，避免拖动中反复跨 JS 桥接调用 `resize_window`；边框随明暗主题调整。其他平台保留合并到动画帧的兼容路径。
- 修正窄窗口 PDF 页码表单被两个固定宽度输入框撑出的裁切问题。
- 文件分类预览不再创建目标目录；撤销复制分类时返回实际清理数量，并保留源文件及已有同名目标。

## 验证

- Python 178 项、前端契约 25 项，静态检查无错误；前端保留 141 项既有样式/规范警告。
- 真实 AES-128/256 文件覆盖正确、错误、缺少及空打开密码，检查切割、拆分、合并的输出页内容、顺序和源文件保留。普通 PDF、Unicode 密码、同名输出保护也纳入回归。
- PyInstaller onefile AES 探针实际解密并读取页文本，加入 Windows/macOS/Linux CI 发布门槛。Windows 实际文件夹版冻结应用通过桌面桥接、队列和隔离 worker 完成 AES-256 切割，重新读取输出验证第 3 页、第 1 页的顺序；实际包内 RapidOCR/ONNX 引擎也完成清晰英文数字图片识别与文本导出。
- Windows 本机 200% / 192 DPI 原生探针验证启动工作区、最小尺寸、最大化/还原、边缘命中及快速释放路径；另用实际鼠标输入验证四条边、右下角缩放与最小窗口。窗口尺寸变化有原生事件记录，过程没有 JS 逐帧缩放请求。实际主窗口三次启动的宽高与位置一致，未累积缩小。
- 小窗口检查覆盖 640×400 至实测最小内容区 603×341：首页、PDF 切割、文件搜索、文本 JSON 的关键控件可滚动到达并可命中；完整工作区流程与 14 模块导航巡检继续执行。

证据及命令见 [verification.json](https://github.com/jdassd/PPX_lobechat/blob/v2.17.2/docs/releases/assets/v2.17.2/verification.json)。三平台 CI 全部成功后才创建 Release；发布包对应已推送的 Tag 提交。

125% / 150% DPI 仅有几何规则模拟，未做对应硬件实测；本轮没有连续拖动的视频或逐帧闪烁测量，不能将前后截图视为动态视觉验收。多屏硬件、三平台安装/升级/恢复、更广的 OCR 文档/表格场景和 LibreOffice 等尚未完成的验收继续按 [验收记录](https://github.com/jdassd/PPX_lobechat/blob/v2.17.2/docs/refactor-acceptance.json) 保持 pending，不承诺所有环境没有问题。
